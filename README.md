# Утилита ИИ-ревью тест-кейсов DoQA

Автоматизирует проверку тест-кейсов в DoQA статусе `review` с помощью ИИ
по правилам из файла `DoQA_test_case_review_rules_`.

## Алгоритм работы

1. Получает список проектов (пространств) и их id из DoQA (`GET /api/project`).
2. Получает список пользователей — создателей кейсов и ответственных (`GET /api/user`).
3. Предлагает пользователю выбрать фильтры: **пространство**, **дату обновления**, **автора**.
4. Запрашивает тест-кейсы по фильтрам (`POST /api/testcase/search`):
   - `spaceId` — выбран на шаге 3
   - `statuses: ["review"]`
   - дата обновления — выбрана на шаге 3
   - `creatorIds` — выбраны на шаге 3
5. Передаёт кейсы + правила из файла `DoQA_test_case_review_rules_*` в ИИ с промтом.
   Промт хранится в файле `prompt.txt` и **перечитывается перед каждым обращением к ИИ**
   (можно редактировать прямо во время работы утилиты).
6. Результат сохраняется в файл:
   `Ревью<ГГГГ-ММ-ДД_ЧЧ-ММ-СС> кейсов из пространства <пространство> c автором <creatorIds>.md`

## Установка

```bash
pip install -r requirements.txt
```

## Настройка (переменные окружения или файл `.env`)

| Переменная        | Описание                                        |
|-------------------|-------------------------------------------------|
| `DOQA_BASE_URL`   | URL инстанса DoQA, напр. `https://doqa.company.ru` |
| `DOQA_API_KEY`    | API-ключ DoQA                                   |
| `OPENAI_API_KEY`  | Ключ ИИ (OpenAI-совместимый API)                |
| `OPENAI_BASE_URL` | (опц.) свой endpoint, напр. локальная модель    |
| `OPENAI_MODEL`    | (опц.) имя модели, по умолчанию `gpt-4o-mini`   |

Также все параметры можно передать аргументами командной строки
(`--base-url`, `--api-key`, `--openai-api-key`, `--model`, `--batch-size`).

## Запуск

Интерактивный режим (выбор режима и фильтров через меню):

```bash
python doqa_review_util.py
```

Доступные режимы:
1. Ревью по фильтрам (пространство, дата обновления, автор).
2. Ревью конкретного списка кейсов по id (`--case-ids 123,456` или файл со списком id).
3. **Ревью кейсов из файла экспорта DoQA** (`--case-file <путь>`).

### Ревью кейсов из файла (формат экспорта DoQA)

В качестве входного файла используется экспорт тест-кейсов из DoQA:
основной формат — **XLSX** (экспорт «Test Cases → Excel»), дополнительно
поддерживаются **CSV** (разделитель `;`/`,`/таб определяется автоматически,
кодировка UTF-8 с BOM) и **JSON**.

Формат табличного экспорта: одна строка = один шаг тест-кейса; колонки
`ID`, `Title`, `Status`, `Priority`, `Folder Title`, `Precondition`,
`Action`, `Data`, `Expected Result`, `Comment` (имена колонок распознаются
и на русском: `Название`, `Статус`, `Действие`, `Ожидаемый результат` и т.п.).
Поля кейса могут повторяться в каждой строке либо быть заполнены только в
первой строке кейса; строки без `ID` считаются продолжением предыдущего кейса.

Загрузка кейсов идёт **из файла, без обращения к API за самими кейсами**
(DoQA нужен только для получения списка пространств — он используется для
имени файла результата).

```bash
# неинтерактивно: все кейсы из файла (можно несколько файлов через запятую)
python doqa_review_util.py --non-interactive --space-id 7 \
    --case-file "Test Cases export.xlsx"

# интерактивно: выбрать режим [3], указать файл и при желании часть id из него
python doqa_review_util.py
```

Результат сохраняется в тот же формат имени файла:
`Ревью<дата_время> кейсов из пространства <пространство> c автором кейсы_<id>.md`.

Неинтерактивный режим (для cron/CI):

```bash
python doqa_review_util.py --non-interactive \
    --space-id 7 --creator-ids 1,2 \
    --updated-after 01.10.2026 --updated-before 20.10.2026
```

## Файлы проекта

- `doqa_review_util.py` — сама утилита
- `DoQA_test_case_review_rules_.md` — файл правил (пример; замените на свой, имя должно начинаться с `DoQA_test_case_review_rules_`)
- `prompt.txt` — файл промта (создаётся автоматически при первом запуске, редактируется freely)
- `test_run.py` — автотест против фейкового DoQA API и фейковой ИИ-модели (`python test_run.py`)

## Примечание про API DoQA

Утилита использует типовые эндпоинты DoQA REST API (`/api/project`, `/api/user`,
`/api/testcase/search`), ключ — параметром `apiKey`. Если в вашем инстансе пути/поля
отличаются (разные версии API), поправьте методы класса `DoQAClient` — они изолированы.
Парсинг ответов устойчив к формату «массив» или «объект со списком».
